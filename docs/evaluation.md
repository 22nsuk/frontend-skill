# 초안 평가 사례

이 문서는 스킬의 범위와 판단을 확인하기 위한 사례 모음입니다. 실행 결과나 성능 벤치마크가 아닙니다. 스킬의 필수 읽기 경로에서도 제외합니다.

## 평가할 것

- 사용자의 변경·보존 범위에 맞게 작업하는가.
- 선택한 표현을 내용과 독자의 과업으로 설명할 수 있는가.
- 특정 색·서체·레이아웃을 이유 없이 제거하거나 강제하지 않는가.
- 필요한 참고 문서만 선택하고 불필요한 기능·도구·승인 단계를 만들지 않는가.
- 내용과 동작의 보존, 실제로 실행한 검증, 남은 제한을 정확히 구분하는가.

## 사례

| 사례 | 요청 예시 | 관찰 기준 |
| --- | --- | --- |
| 새 소개 페이지 | 지역 수리 서비스의 소개 페이지를 만들어줘. 제공한 서비스·가격·예약 링크를 사용해줘. | 실제 자료와 신청 경로가 드러나고, 사진·고객 후기·가격을 추가로 지어내지 않는다. |
| 작은 개선 | 보라색 그라데이션 로고와 현재 서체는 유지하고 메뉴 간격만 다듬어줘. | 보호한 브랜드를 유지하고 간격과 직접 관련된 부분만 변경한다. |
| 전면 리디자인 | 핵심 조건과 신청 경로가 뒤섞인 기존 페이지를 다시 구성해줘. 내용·브랜드·신청 동작은 유지해줘. | 정보 순서와 배치는 재검토하되 중요한 조건이나 기능을 삭제하지 않는다. 현재 순서를 무조건 보존하지 않는다. |
| 비교 대시보드 | 제품 네 개의 월별 추세를 같은 척도로 비교할 수 있게 정돈해줘. | 동일 크기 차트나 유용한 스파크라인을 형식적 이유로 제거하지 않으며 값·축·기간을 유지한다. |
| 복합 작업 | 공개 소개 페이지의 성능 비교 차트와 조건 선택 필터를 개선해줘. 수치와 선택 결과는 유지해줘. | 페이지·데이터·조작에서 실제로 영향을 받는 참고 부분을 선택하고, 이 사례와 작은 간격 수정의 읽기 범위를 구분한다. |
| 한국어 보고서 | 긴 한국어 제목, 날짜, 단위, 출처가 있는 보고서를 다시 디자인해줘. | 긴 내용과 좁은 화면을 고려하고 중요한 조건을 숨기거나 글자 축소만으로 해결하지 않는다. |
| 표현이 강한 페이지 | 음악 행사의 역동적인 페이지를 만들어줘. 일정과 예매 링크는 항상 찾기 쉬워야 해. | 요청한 표현성을 구현하되 일정·예매·모션 감소 경로가 유지된다. 회색 위주의 고정 스타일로 바꾸지 않는다. |
| 검토 전용 | 이 화면을 검토하고 수정 제안만 알려줘. | 파일이나 설정을 바꾸지 않고 관찰과 제안을 구분한다. |
| 제한된 도구 | 이미지를 새로 만들 수 없는 환경에서 제공한 텍스트와 표로 완결된 안내 페이지를 만들어줘. | 가짜 자산 경로나 빈 장식 칸에 의존하지 않는다. 실행하지 못한 화면 검사는 미확인으로 남긴다. |
| 적용 제외 | 화면은 그대로 두고 서버의 재시도 로직만 고쳐줘. | 시각 디자인 절차를 불필요하게 시작하지 않는다. |

이 입력들은 간략한 예시입니다. 실제 실행 시에는 변경 대상, 보존할 자료, 사용 환경, 요청한 결과를 담은 독립적인 사례를 준비합니다. 기대 결과나 리뷰어의 진단을 실행자에게 답안으로 제공하지 않습니다.

## 확인 방법과 범위

초기 확인은 최종 파일을 대상으로 이름·설명·메타데이터와 상대 참조가 일치하는지, 불필요한 실행 의존이나 강제 중지 절차가 없는지 점검합니다. 이 확인은 실제 호스트의 발동이나 생성 품질을 검증하지 않습니다.

동작을 평가할 때는 실행자에게 해당 스킬과 요청을 주고 실제 산출물·변경 내역·도구 기록을 확인합니다. 강제로 스킬을 읽힌 실행은 적용 행동의 관찰이며 자동 발동 검증으로 세지 않습니다. 발동을 평가하려면 스킬이 제공된 환경에서 선택 여부를 따로 관찰합니다.

같은 자료·환경·모델에서 비교하고, 품질을 해치는 내용 누락·기능 회귀와 취향 차이를 분리합니다. 단일 결과로 일반적인 우월성을 주장하지 않습니다. 시간·토큰을 비교한다면 실패·수정 반복과 필요한 도구 작업까지 포함하며, 문서 바이트 수를 토큰 수로 대신하지 않습니다.

유효한 장점이 없거나 의도하지 않은 변경이 늘면 해당 지침의 범위와 구체성을 다시 검토합니다. 평가 때문에 새 운영 도구나 큰 테스트 체계를 의무로 만들지는 않습니다.
