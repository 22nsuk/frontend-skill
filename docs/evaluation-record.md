# 평가 기록서식

평가자가 실행자의 작업 폴더 밖에 복사해 사용하는 빈 서식입니다. 사례·조건·판정 기준은 [평가 문서](evaluation.md), 기록 원칙은 [실행별 기록 항목](evaluation.md#실행별-기록-항목)을 참조합니다.
필요한 구역·행만 사용하고, 기존 로그·Git 기록에 있는 값은 그 위치와 해당 구간으로 갈음합니다. 빈칸은 통과·0·완료를 뜻하지 않으며, 확인하지 못한 항목에는 미관찰과 이유를 적습니다.

## 3. 산출물과 측정 이력

최초본의 응답·생성 파일은 검수나 수정 전에 보관합니다. 원문 파일의 보관 위치와 동일성 확인용 해시는 별개이며, 해시만으로 원문 보관을 대신하지 않습니다.

| 산출물 ID | 단계(최초본·검수 수정·추가 요청) / 시각 | 부모 산출물 ID | 수행자(actor) / 요청·수정 사유 | 원문 파일 위치 또는 Git 커밋·보관 저장소·번들 | 해시·diff·요청 등 근거 |
| --- | --- | --- | --- | --- | --- |
| | | | | | |

Git 보관본을 사용했다면 새 경로의 복원 커밋 확인 결과, 별도로 보관한 필수 파일과 상대 경로, 진입점과 로컬 리소스 또는 해당 사례의 검사를 기록합니다. 복원 검증 판정과 근거를 연결합니다.

수정 후 성공을 최초 성공으로 소급하지 않습니다. 결과가 없는 시도도 2구역에 남기며, 추가 요청은 변경된 요청과 앞선 산출물의 연결을 기록합니다.

| 측정 ID | 산출물 ID·측정 파일 | 단계·기준 ID | 폭(CSS px: 요청 / 실측) | 측정 구간·상태(시각·선택값·인쇄 등) / 구간 중 파일 고정 여부 | 관찰값·근거 위치 | 판정(통과·실패·미관찰)·이유 |
| --- | --- | --- | --- | --- | --- | --- |
| | | | | | | |

후속 정정은 원래 기록을 지우지 않고 연결합니다. 재측정은 새 측정 ID를 부여합니다.

| 정정 ID / 시각·수행자 | 원래 측정·판정 ID | 정정 사유 | 새 산출물·측정 ID / 근거 | 정정된 판정·영향 범위 |
| --- | --- | --- | --- | --- |
| | | | | |

검토 전용 사례의 snapshot은 같은 작업 폴더의 전후 변경을 확인하는 기록이며 원문 파일 복사본이 아닙니다. snapshot·Git·도구 기록으로 확인한 범위와 확인하지 못한 범위를 해당 측정 행에 구분합니다.
